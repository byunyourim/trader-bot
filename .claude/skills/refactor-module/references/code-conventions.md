# 리팩토링 컨벤션

## 반복 코드 분리 기준

| 상황 | 판단 |
|------|------|
| 3곳 이상 반복 | 분리 우선 검토 |
| 2곳 반복 — 일반 로직 | 분리하지 않는다 |
| 2곳 반복 — 권한·validation·business rule·금액·날짜 계산 | 분리할 수 있다 |
| 1곳에서만 사용 | 미래 확장만으로 추상화 금지 |

## 리팩토링 전 체크

- public API·export 목록을 먼저 파악한다 (시그니처 변경 시 사용처 전수 수정)
- 동작 변경과 리팩토링을 한 PR에 섞지 않는다
- 테스트가 없는 위험한 로직은 리팩토링 전 테스트를 먼저 추가한다

## 리팩토링 후 기준

아래 중 하나 이상이 실측으로 개선되어야 완료:

- 중복 감소
- 복잡도(함수 길이·조건 depth) 감소
- 이름 명확성 증가
- 책임 분리
- 테스트 용이성 증가
