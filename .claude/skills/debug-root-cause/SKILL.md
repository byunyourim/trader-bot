# debug-root-cause

목표: 가장 가능성 높은 원인을 증거 기반으로 찾고, 최소 수정안을 제시한다.

## 워크플로우

```txt
1. 에러 메시지 그대로 읽기
2. 실패 위치와 조건 추출
3. 관련 파일만 탐색
4. 원인 후보 순위화
5. 최소 수정안 제시
6. 검증 명령 제시
```

## 규칙

- 에러 문구를 무시하지 않는다.
- 파일/라인/명령을 먼저 본다.
- 관련 없는 리팩토링을 하지 않는다.
- 원인이 불확실하면 확률과 근거를 분리해서 말한다.
- 한 번에 큰 수정보다 작은 재현/검증을 우선한다.

### 수정 후 필수 검증 (순서 준수)

1. 수정한 파일을 import하는 모듈에 사이드 이펙트 없는지 확인
2. `npm run build` — 빌드 성공 확인 (실패 시 미완료, 재수정)
3. `npm test` — 기존 테스트 전부 통과 확인
4. 버그 재현 케이스가 있으면 regression test 추가 여부 판단

## 출력 형식

```md
## 가장 가능성 높은 원인
## 근거
## 다른 가능성
## 최소 수정안
## 검증 방법
## 리스크
```
